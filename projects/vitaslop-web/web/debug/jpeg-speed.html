JPEG: this build's decoder, or the browser's

SceJpeg is a synchronous guest call and every browser JPEG entry point is a promise, but a host call can wait on one here - that is what every blocking kernel primitive already does through JSPI. So the browser's decoder is reachable and the question is only which is faster on the device you are holding. The comparable number is bitmap+read: the guest needs pixels in its own memory, so the browser path has to draw the bitmap and read it back, and comparing decode against decode would flatter it.
